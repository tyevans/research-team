# Adopting eventsource 0.14.0's two new capabilities

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete `domain/targeting.py` now that the library rejects a foreign `aggregate_id` itself, and replace `apply_schema`'s regex-parsed column reconciliation with the library's pure `generate_additive_migration`.

**Architecture:** Two independent halves. The first removes a mixin from five aggregates and proves, per aggregate, that the library still catches what the mixin caught. The second changes the middle of one function and fixes one store that never called it.

**Tech Stack:** Python 3.13, `eventsource-py` 0.14.0, pydantic v2, aiosqlite, pytest.

**Spec:** `docs/superpowers/specs/2026-08-13-adopting-0140-design.md` — read it first. It records why both obvious adoptions are the wrong ones, and that reasoning is the point of the change.

- [ ] **Step 2: Find each aggregate's creation command and confirm it stamps off the command**

**This is the load-bearing step of the whole task.** The library only inspects the event. If any aggregate's `decide` stamps the event from `state` instead, deleting the mixin removes a real check and nothing replaces it — that aggregate must keep the mixin, and you must say so in your report rather than deleting it anyway. `corpus.py:166-168` is the confirmed example with a comment stating why.

- [ ] **Step 3: Write one test per aggregate**

Five tests, each executing the creation command against an aggregate with a *different* id and asserting the library refuses. Shape (adapt names to what each aggregate actually needs — the sketch below is not a claim about signatures):

```python
def test_a_corpus_refuses_a_command_naming_another_corpus() -> None:
    """The library rejects the event, now that the mixin does not reject the command.

    `decide` stamps the creation event's `aggregate_id` from the command,
    because a fresh corpus has no id in state -- so a mistargeted command
    produces a mistargeted event and `_reject_foreign_aggregate_id` sees it.
    That is the whole reason `ChecksCommandTarget` could be deleted, and it
    is a fact about this aggregate's `decide` rather than about the library.
    """
    mine, theirs = uuid4(), uuid4()
    corpus = Corpus(mine)

    with pytest.raises(AggregateIdMismatchError) as caught:
        corpus.execute(StoreSourceDocument(corpus_id=theirs, ...))

    assert str(theirs) in str(caught.value)
    assert "StoreSourceDocument" in str(caught.value)
```

Assert on `AggregateIdMismatchError` and on the message naming both the foreign id and the command class. Do **not** assert the full message string — it is the library's to word.

### Task 2: `apply_schema` takes the library's generator

**Files:**
- Modify: `research_team/infrastructure/persistence/read_models.py` — `_column_definitions:245`, `apply_schema:269`, `CorpusStore.open:729`
- Test: `tests/infrastructure/test_read_model.py`, `tests/infrastructure/test_corpus_read_model.py`

- Produces: `apply_schema(connection, model)` unchanged in name and signature.

- [ ] **Step 1: Write the test that the current code fails**

The gain is that a refusal now leaves the table untouched. Today the loop `ALTER`s one column at a time and SQLite refuses a `NOT NULL`-with-no-default partway through, after applying the earlier ones.

Add to `tests/infrastructure/test_read_model.py`:

```python
async def test_a_refused_reconcile_leaves_the_table_untouched(tmp_path) -> None:
    """A model that cannot be reconciled must add none of its columns, not some.

    The old loop issued one ALTER per missing column and let SQLite refuse the
    impossible one mid-way, so a model that grew two fields -- one addable, one
    NOT NULL with no default -- left the table half-widened and the error
    naming only the second. `generate_additive_migration` raises before
    returning any statement, so the refusal is atomic.

    Fails against the previous implementation by finding the first column
    present after the raise.
    """
```

Build it by creating a table from a narrow model, then reconciling against a wider one whose added fields are (a) nullable and (b) `NOT NULL` with no default, asserting the raise and then asserting via `PRAGMA table_info` that **neither** column arrived.

Read the file's existing helpers first — `test_a_database_written_before_a_field_existed_gains_its_column` is the neighbouring test and already builds an old database. Reuse its machinery.

- [ ] **Step 2: Prove it red**

Run: `uv run pytest tests/infrastructure/test_read_model.py -k refused_reconcile -v`
Expected: FAIL, because the nullable column was added before the refusal. Capture the output.

- [ ] **Step 3: Rewrite `apply_schema`'s middle**

Keep the `CREATE TABLE IF NOT EXISTS` first step and the signature. Replace the `_column_definitions` loop:

```python
async def apply_schema(connection: aiosqlite.Connection, model: type[ReadModel]) -> None:
    await connection.executescript(model_schema(model))
    existing = {
        row[1]
        for row in await (
            await connection.execute(f"PRAGMA table_info({model.table_name()})")
        ).fetchall()
    }
    # `generate_additive_migration` is pure and raises before returning
    # anything, so a model with an unaddable column leaves the table as it
    # was rather than half-widened. The local loop it replaces let SQLite
    # refuse the impossible column after the addable ones had landed.
    #
    # The library's `reconcile_read_model_schema` would do the PRAGMA too,
    # and is not used: it takes a SQLAlchemy connection, and every store here
    # owns a raw aiosqlite one. Threading an engine through two `open()`
    # classmethods to buy behaviour this already has is the wrong trade.
    for statement in generate_additive_migration(model, existing, dialect="sqlite"):
        await connection.execute(statement)
    await connection.commit()
```

Delete `_column_definitions` entirely, and delete `re` from the imports if nothing else uses it. Keep `model_schema`.

Preserve the existing docstring's reasoning — the `SessionSummaryRow` incident it records is why the function exists — and update only the sentences describing the mechanism.

- [ ] **Step 4: Green, and the old-database test still passes**

Run: `uv run pytest tests/infrastructure/test_read_model.py -v`
Expected: PASS, including `test_a_database_written_before_a_field_existed_gains_its_column`, which is the regression surface for this rewrite.

- [ ] **Step 5: Write the failing test for `CorpusStore`**

- [ ] **Step 7: Fix `CorpusStore.open`**
